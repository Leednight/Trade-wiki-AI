## 2. Phase 1: 基础骨架 (Week 1-4)

## 5. 持续演进

### 5.1 模型升级路径

```
当前: Qwen2.5-7B Q4 (6GB显存)
    │
    ├── 升级1: Qwen2.5-14B Q4 (10GB显存)
    │   └── 时机: RTX 50系 / 显存充足时
    │
    ├── 升级2: Qwen3-7B/14B
    │   └── 时机: 新一代基座模型发布
    │
    └── 升级3: 专业交易微调模型
        └── 时机: 开源交易领域模型出现
```

### 5.2 功能扩展方向

| 方向 | 描述 | 优先级 |
|------|------|--------|
| 微信/TG集成 | 扩展IM渠道 | 中 |
| 研报自动入库 | 接入研报API，自动解析入库 | 中 |
| 多品种联动分析 | 跨品种策略关联 | 低 |
| 语音交互 | 飞书语音消息 → Whisper转录 → 处理 | 中 |
| 多用户支持 | 家庭/团队共用，各自独立风格 | 低 |
| Web UI | 独立管理界面 (策略/知识/配置) | 中 |
| 移动端推送 | 微信/短信紧急预警 | 高 |

### 5.3 技术债务管理

```
每个Phase结束时:
├── 记录技术债务清单
├── 评估债务优先级
├── 安排下一个Phase的债务清理时间
└── 避免债务累积到不可控
```

## 6. 风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| 蒸馏数据不足，效果不佳 | 高 (初期) | 中 | 影子蒸馏自动生成数据；降低Phase 2验收标准，渐进提升 |
| 本地小模型能力天花板 | 中 | 中 | 保持云端降级能力；适时升级14B模型 |
| 飞书API变更 | 低 | 高 | 抽象IM接口层，快速适配 |
| GPU显存不足 | 低 | 高 | 量化升级(Q4→Q3)；推理和训练时分时复用 |
| 用户使用频率低 | 中 | 中 | 主动推送增加粘性；对抗式蒸馏主动交互 |
| 训练过拟合 | 中 | 中 | 严格验证集监控；Early Stopping |
| 时间投入不够 | 高 | 中 | Phase 1优先级最高，确保基础可用；后续Phase可并行 |

## 8. Quick Start (Phase 1 Week 1)

```bash
# 1. 克隆项目
cd /workspace/Trade-wiki-AI

# 2. 创建Python环境
uv venv .venv
source .venv/bin/activate

# 3. 安装依赖
uv pip install fastapi uvicorn lark-oapi ollama chromadb

# 4. 安装Ollama + 拉取模型
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5:7b-instruct-q4_K_M

# 5. 启动ChromaDB
docker run -p 8001:8000 chromadb/chroma

# 6. 配置飞书应用
cp .env.example .env
# 编辑 .env 填入飞书 App ID / Secret

# 7. 启动内网穿透
cloudflared tunnel --url http://localhost:8000

# 8. 启动服务
uvicorn src.main:app --reload

# 9. 在飞书中给Bot发消息测试
```
