## 1. 产品概述

### 1.1 产品定位

Trade-Wiki-AI 是一个**可成长的个人交易知识助手**，基于用户交易书籍、交易员经验视频构建专属知识库，通过持续的教学交互和模型蒸馏，逐步内化用户的交易思维风格，最终成为用户交易决策的智能伙伴。

### 1.2 核心理念

| 理念 | 说明 |
|------|------|
| **知识私有化** | 所有交易策略、持仓数据绝不离开用户本机 |
| **助手可成长** | 通过蒸馏技术，助手从"检索工具"进化为"思维镜像" |
| **成本可控** | 本地小模型处理80%日常问题，云端大模型仅在必要时调用 |
| **交互无感** | 通过飞书等IM直接沟通，融入日常工作流 |

### 1.3 目标用户

- 个人交易者（期货/股票/加密货币）
- 有自己的交易体系，希望系统化管理交易知识
- 追求交易决策的一致性和可复盘性
- 对数据隐私有较高要求

### 2.2 典型使用场景

#### 场景A：盘前准备（每日）

```
08:30  助手主动推送：
       "早上好！今日关注品种：螺纹钢临近突破位3850，
        基于你的突破回踩策略，建议重点监控。"

08:35  你："螺纹钢最近资金面怎么样？"
       助手：[检索知识库+行情数据]
       "根据你收藏的《资金面分析法》，近期持仓量持续增加，
        与价格突破形成共振，符合你'量价配合'的偏好。"

08:40  你："如果突破，我计划入场1/3仓位"
       助手："已记录。这与你'分批建仓'的原则一致。
        另外提醒：你的止损位建议设在3780，
        基于你教过的'突破位下方1%'规则。"
```

#### 场景B：教学交互（不定期）

```
你："我今天想教你一个新思路——持仓过夜的条件"
助手："好的！请告诉我，你在什么情况下会选择持仓过夜？"

你："首先趋势必须明确，均线多头排列；其次收盘价在关键位之上；
     第三，当晚没有重大数据公布"
助手："理解了。我来确认：
     条件1: 趋势明确 → 均线多头排列
     条件2: 收盘价站上关键支撑位
     条件3: 无重大数据事件
     这三个条件必须同时满足吗？还是有权重？"

你："必须同时满足，缺一不可"
助手："已保存为策略卡片「持仓过夜三条件」。
     这和《以交易为生》中提到的隔夜持仓规则有相似之处，
     但你的版本更严格（要求三条件同时满足）。
     是否需要关联到你的交易日志进行后续验证？"
```

#### 场景C：复盘反思（盘后）

```
你："今天那单螺纹钢做错了，我追涨了"
助手："让我看看...你今天在3860入场，
     但你的突破回踩策略要求等回踩确认。
     是什么让你偏离了自己的策略？"

你："放量太猛了，怕错过就冲进去了"
助手："这和你上次做错镍的原因很像——
     放量突破容易触发你的FOMO情绪。
     你之前说'等回踩确认'就是为了过滤这种假突破。
     建议把这个错误模式记录下来，下次放量时
     我会额外提醒你'回踩确认优先'。"

你："好，记下来"
助手："已记录错误模式#7：放量突破→FOMO→追涨。
     当前你的策略一致性评分：78%。
     随着这类偏差被纠正，评分会提升。"
```

### 3.2 详细功能说明

|--------|---------|------|------|------|--------|

| F1.2 | 视频导入与转录 | 通过Whisper将交易视频转录为文本，支持中英文 | 视频文件/URL | 转录文本+时间戳 | P0 |

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 本地问答延迟 | < 1.5s | 从消息接收到回复发送 |
| 云端问答延迟 | < 5s | 含API调用时间 |
| 知识检索延迟 | < 500ms | 单次RAG检索 |
| 路由决策延迟 | < 300ms | 意图分类+隐私检测 |
| 并发处理 | ≥ 5条消息/秒 | 满足个人使用场景 |
| 系统可用性 | ≥ 99% | 断网时本地功能仍可用 |

### 4.2 安全要求

| 要求 | 说明 |
|------|------|
| 零数据泄露 | 持仓/账户/策略参数等绝不出本机 |
| 脱敏可逆 | 脱敏数据送云端后，回复可在本地还原上下文 |
| 数据加密 | 本地敏感数据AES-256加密存储 |
| 访问控制 | 飞书Bot仅响应授权用户 |

### 4.3 成本要求

| 指标 | 目标 | 说明 |
|------|------|------|
| API调用占比 | ≤ 20% | 80%问题本地解决 |
| 月度API费用 | ≤ ¥50 | 通过缓存+预计算+本地化降低 |
| 硬件要求 | RTX 3090/4090 (24GB) | 支持Qwen2.5-7B Q4量化推理+QLoRA训练 |

### 4.4 可扩展性

| 方面 | 说明 |
|------|------|
| 基座模型可替换 | 支持从7B升级到14B，或更换模型系列 |
| 知识库可扩展 | 支持从ChromaDB升级到Milvus，从SQLite升级到PostgreSQL |
| IM渠道可扩展 | 先飞书，后续可扩展到微信/Telegram |
| 知识源可扩展 | 先PDF/视频，后续可接入网页/研报API |

## 8. 风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 蒸馏数据量不足 | 模型无法有效学习 | 中 | 影子蒸馏自动生成对比数据；云端大模型辅助扩充 |
| 小模型能力天花板 | 复杂推理始终需要云端 | 中 | 支持升级到14B模型；保持云端降级能力 |
| 飞书API变更 | Bot功能中断 | 低 | 抽象IM接口层，支持快速切换 |
| 训练过拟合 | 模型只记住不泛化 | 中 | 保留20%数据做验证；Early Stopping |
| 隐私检测误判 | 敏感数据泄露 | 低 | 白名单机制+关键词正则+模型三重检测 |
